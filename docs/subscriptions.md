# 订阅管理

> 2026-10-06：主订阅输入上限调整为 1 MiB，资源快照外壳上限为 2 MiB；节点/组容量与验证说明见 [通用兼容性记录](general-yaml-compatibility.md)。来源 URL、刷新、回滚和网络预算不变。下文旧日期记录保留当时限制。

## 手机上使用

从首页进入“管理订阅”。列表显示当前订阅、VPN 真实状态、保存数量、每份配置的节点/策略组/规则数量和导入时间。

1. 点击“导入配置文件”，选择本地文件并阅读适配与存储说明，再点“确认保存”。名称使用文件名，去掉 `.yaml` / `.yml` / `.txt` 后缀。文件内容先通过现有结构和兼容性校验；失败不会替换已有记录。
2. 未连接时可以勾选“设为当前订阅（不连接）”；连接中只保存新订阅。点击列表订阅主体即可切换；未连接时只改变当前配置，连接中先确认重连。右侧箭头仅打开详情，详情中的切换入口也保留。确认后先等待旧隧道停止，再选择新记录并请求启动。断开等待超过 15 秒时保留原选择，显示失败，不强行启动第二条隧道。
3. 每份订阅各自记住节点选择。选中的订阅可进入“节点与策略组”；未连接时保存选择供下次连接使用，已连接时可热切 select 组；已有连接保持原路径，详见 [节点与诊断说明](node-and-network-diagnostics.md)。列表的“当前”标记表示所选配置，VPN 是否连接以系统状态为准。
4. 详情页可以重命名、删除，也可在列表侧滑删除，或点右上角“选择”进行多选删除。删除有确认；包含当前订阅时会先断开。删除后不自动选择或连接另一份。原始 YAML 文件保留，恢复时需重新导入。

相同原文且来源 URL 相同的重复导入沿用同一条记录，更新文件名与统计，保留已有节点选择；同名但内容不同会另存一份，名称加 ` (2)` 等序号。最多 128 份，每份最多 512 KiB。不自动合并同名配置。HTTPS 链接导入现在安全保存来源，支持手动刷新、差异确认和版本回滚；不自动定时刷新或跨设备同步。文件导入可在详情中补充来源链接。协议与导入格式已按 [兼容性扩展](compatibility-expansion.md) 增加；providers、自动策略组和高级规则/DNS 尚未接入。


## 兼容性诊断与版本维护（2026-10-03）

### 入口与流程

- 订阅列表、导入预览、详情及维护页的 Info 图标进入诊断。详情针对该已保存配置；导入失败后，列表 Info 保留最近候选的诊断；维护刷新失败后，维护页 Info 保留候选诊断。
- “直接支持／需要适配／无法使用”汇总顶层字段、各节点字段、策略组、逐条规则及 DNS 错误。语法有效时继续收集，不因第一项错误提前退出；YAML 语法、编码、单文档形状不合法时须先修复语法。最终仍以原有严格校验器为准，不静默移除字段。
- Info 内有固定虚构样例，与 `Examples/compatibility/` 文件及离线回归使用同一来源。它们覆盖当前目标订阅的协议结构，不包含真实节点、真实令牌，也不承诺覆盖所有服务商配置。
- 订阅详情 → “刷新与版本历史”：设置来源、手动刷新、查看当前版本和历史版本。旧版未保存的 URL 无法追溯，需要本人重新输入。仅设置 URL 不请求网络，不中断已连接 VPN。
- 下载成功先诊断并预览差异：节点增删和字段变化数量、策略组／规则／DNS／其他设置变化、失效选择数量。差异不显示节点名称、地址、密码或 URL；服务器只改密码也会记为节点字段变化。原文相同不创建版本。
- 确认后才替换。旧选择仍存在时保留，失效时明确计数并采用配置中组的首选项。活动配置内容变化且正在连接时，单独确认断开／重连；非活动配置或未连接状态仅保存。
- 回滚恢复该历史版本的 YAML 和选择，生成递增的新版本，保留被替换版本；来源 URL 保持当前来源。每份保留最近五个历史快照，另保留最近一次首页 Ping 请求成功的快照。未有成功请求的版本只标记“已校验”，不称为已验证可用。

### 存储、失败及恢复

来源 URL（含令牌）、原文、选择与历史都在 `AfterFirstUnlockThisDeviceOnly` 共享钥匙串中，禁止同步；UI 来源输入为 SecureField，不回填已保存 URL。URL 最多 8192 UTF-8 字节，继续采用 HTTPS、最多五次同源跳转、512 KiB 体积限制以及临时 URLSession。没有公共转换服务。

每次替换写新记录，最后原子提交索引指针；提交前旧记录保持可读。索引提交失败保留原版本并清理候选；过期预览不能覆盖新内容。删除订阅会清理全部历史和来源，失败继续用已有待清理机制。历史有数量上限，但接近 512 KiB 的大型配置及满历史记录的真机内存仍未压测。

第一次版本更新将索引升级为 `clash-subscriptions-v2`，旧 App 会拒绝读取，避免旧版清理逻辑误删新记录。新 App 可读旧索引和缺少版本字段的旧数据。降级不能直接使用新版索引；请保留原始文件及已验收源码／签名归档，不以构建临时目录充当备份。

启动恢复规则：

1. 正在连接时应用更新，先停旧隧道，再提交新版本。等待最多 25 秒，要求系统 connected 且扩展遥测中的配置标识匹配。若写入失败且旧隧道已停止，尝试重新启动未被替换的旧版本。
2. 新版本启动失败，停候选、恢复更新前版本，再尝试启动一次，不无限重试。离线保存的更新在以后手动连接时执行相同启动检查；失败优先用最近一次请求成功快照，否则上一快照。首次启动检查标记持久化，重新打开 App 不会丢失该检查要求。
3. 用户主动点击断开取消恢复，不在 App 启动时擅自连接。App 被终止／锁定钥匙串、系统连接中断或恢复自身失败时，保留历史并展示真实状态，需本人再次打开页面处理。不会保证在 App 被终止后继续执行恢复。
4. “启动成功”只证明系统隧道和相应内核运行，不能判断节点可达、认证有效或 DNS／UDP／IPv6 全部正常。服务器失效或 Ping 超时不触发自动回滚。只有成功的首页 Ping 为该源及选择记录一次请求成功，仍不等同全配置验收。

## 早期迁移和切换行为记录

原始 YAML、节点选择、名称及索引都保存在既有共享钥匙串访问组，使用 `AfterFirstUnlockThisDeviceOnly`，禁止 synchronizable。没有把原文保存到 Documents、UserDefaults、普通日志或报告。扩展只读当前记录，其他订阅由主 App 管理。

每份原文与选择使用独立记录，索引最后写入作为提交点。写入新记录后若索引失败，会尝试删除未提交记录；异常退出遗留的孤立记录在下次主 App 读取时清理。删除先提交索引移除和待清理标记，再自动删除钥匙串内容；清理失败的条目不可再选择，标记保留并自动重试，不显示手动清理入口。若索引损坏，不回退到旧条目，以免删除后的凭据意外重新生效。进程中所有写操作在主 App 事务中串行执行，扩展不做迁移或清理。

本机清理在前台使用 utility 工作任务处理：删除后约 1 秒开始，失败后依次等待 5 秒、30 秒重试；一轮最多三次，避免持续占用资源。进入后台暂停后续尝试，回到前台、解锁或新删除时重新调度。已开始的存储事务完成前保留执行槽位，避免前后台切换启动重叠清理。清理不设置页面 busy、不更换提示、不重载当前解析配置或 Ping；更新中的索引代次可阻止旧清理结果覆盖新提交的待清理数量。iPhone／iPad 均移除 Retry cleanup 按钮和待清理区块。该机制只处理本机无引用记录／资源，不删除 iCloud 云端订阅、同步 tombstone 或云端资源。

构建 14 及之前只保存一份配置且没有文件名。第一次正常打开构建 15 会先写新记录和索引，再清理旧条目；中途写入失败保留旧条目。迁移名称为“原有订阅”，不伪造历史文件名和导入日期。可重命名，或重新导入同一文件补全名称、统计；选择继续保留。升级不能找回此前已被旧版覆盖的其他文件，需要本人重新导入。

切换前重新校验目标配置；校验失败不停止现有隧道。确认断开后若存储或新节点启动失败，会保持系统真实失败/未连接状态，不静默连接另一份配置。用户可以切回原订阅手动连接。删除 App 不保证清除钥匙串；删除敏感数据请使用订阅页，并确认没有待清理提示。

## 重复验证与回退

- 运行 `python3 scripts/check-configuration.py`：实际 Swift 校验器、虚构存储测试、固定内核预检；不读取真实钥匙串或连接真实节点。
- DEBUG 构建启动参数环境 `CLASH_SUBSCRIPTIONS_DEMO=1`：隔离示例 UI，可反复切换/删除，重启恢复示例；不能用其验证真实网络。移除此环境变量并重新启动回到真实库。
- `CLASH_OFFLINE_CHECK=1` 会将虚构检查的通过数量和固定用例名写入 `Library/Caches/offline-check.json`。不输出配置、文件名或凭据。
- 升级需保留开发团队、Bundle ID 和钥匙串组。换签名身份可能无法读取旧库，需要本人重新导入原始文件。
- 回退到构建 14 及更早版本前先断开 VPN；这些版本不认识多订阅索引，必须重新导入该旧版本支持的 YAML。不要宣称降级会自动恢复多订阅。保存原始文件、依赖锁定文件和已验收的签名归档；临时构建目录不等于可靠备份。

## 链接导入（2026-10-03）

订阅列表新增“通过链接导入”，输入 HTTPS 地址和可选名称，点击“导入并校验”，检查预览后确认保存。名称留空使用“链接订阅”；不会把 URL 路径、查询参数或服务器文件名自动当作名称。新记录无本地来源文件名；相同内容且来源链接相同的再次导入保留原节点选择；不同来源单独存储，避免丢失来源关系。存储继续采用现有钥匙串提交流程。

- 接收支持范围内的 Clash YAML、仅节点 YAML、节点 URI/列表与 Base64 列表；HTML 登录页不受支持，精确范围见兼容性扩展文档。
- URLSession 临时会话，无磁盘缓存、Cookie 或持久认证存储；URL 在确认导入后与配置一起存入本机钥匙串；取消时不持久化，输入页退出时清空，不写入事件或普通日志。网络原始错误不传播，避免含 URL 的错误被显示/记录。
- 请求头 `Clash.Meta/Clash-iOS`，系统默认 TLS 校验。当前系统网络决定请求路径；不自动启动或切换 VPN，不调用公共转换服务。
- 仅 HTTPS，无 URL 内嵌用户名/密码；允许最多 5 次同源 HTTPS 跳转，拒绝跨域、端口变化或 HTTP 降级。跨站分发需用户输入最终下载地址。
- 配置体最多 512 KiB，检查声明长度与实际读入长度（含解压后字节）；请求等待 20 秒、资源超时 30 秒。允许取消；下载或结构校验失败不提交记录。
- 本轮去掉订阅列表常驻 message 行；文件导入失败改为弹窗，链接导入失败在输入页显示。

验证：下载器使用 URLProtocol 虚构响应测试成功、空体、声明超限、流式超限、HTTP 错误、受限跳转响应、隐藏原始网络错误和取消；URL/重定向策略独立检查通过。`scripts/check-subscription-download.swift` 未发起网络请求。配置/存储自检 63/63（新增链接命名、去重保留选择、本地文件名保留）。模拟器通过虚构下载后预览、保存返回与去重；没有访问真实订阅链接，也没有安装手机。

## 二维码入口（2026-10-03）

## 分享二维码

订阅详情为保存了有效 HTTPS 来源链接的订阅提供「分享二维码」（`qrcode`）入口。独立页面读取最新链接并在本机生成白色码点、透明背景的 PNG 二维码，保留四模块透明静区，直接显示在页面背景上，并通过系统分享导出同一透明图片；不附加说明文案，不请求网络、不写入临时凭据文件，也不更改订阅、同步或 VPN 状态。文件／文本导入且没有来源链接的订阅不显示入口；手动补充来源后可分享。过长链接明确报错，不截断 URL 或 Token。

所有码点保持标准方形。页面用 Canvas 缓存 32 组路径，生成后先等待 0.2 秒，再以 1.2 秒线性总进度播放；保留原有码点渐显曲线，独立随机分配出现时间，不限制方向或位置。随机分组只在生成二维码时确定，后续逐帧渲染沿用，避免闪动。仅错峰淡入，不加缩放，不显示 ProgressView。开启「减少动态效果」时保留短暂等待和整体淡入。最终显示与分享导出使用同一份模块几何，不裁剪二维码或静区。

码点边界按屏幕实际像素对齐，关闭分组填充的抗锯齿，避免淡入期间相邻码点边缘混色产生细缝。分享按钮使用 iOS 26 原生 Liquid Glass 胶囊样式并预留位置，在构建动画总进度一半时（开始后约 0.6 秒）以 0.35 秒缓进缓出曲线局部渐显；开启「减少动态效果」时在短暂淡入的一半触发，按钮淡入缩短为 0.12 秒。出现前不可点击，也不进入辅助功能焦点。中点等待随页面任务取消，重新加载使用独立标识，旧动画不会提前显示新二维码的按钮；分享始终导出完整图片。
