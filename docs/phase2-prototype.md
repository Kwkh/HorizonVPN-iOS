## 手机操作

1. 打开“Clash”，先运行“运行虚构配置自检”。它不读取钥匙串、不访问网络；预期全部通过。
2. 将真实 YAML 留在自己控制的手机位置，打开“管理订阅 → 导入 YAML 文件”。文件如果只在 Mac，可由本人通过 AirDrop 保存到手机本地“文件”位置后选取；无需发进聊天或公共转换服务。原文件不会被 App 删除。
3. 阅读导入页的网络适配和存储说明，确认后才保存到此设备钥匙串。导入失败不会覆盖上一份数据。每份配置单独保留；连接中可以先保存另一份文件，再到详情页确认切换并重连。删除当前订阅会先断开，删除后不自动选择其他订阅。
4. 点击“准备 / 更新 VPN 配置”并确认。旧阶段一配置需要这一步迁移；首次添加时在 iOS 提示中本人允许。没有凭据写入 NETunnelProviderProtocol、serverAddress 或启动 options。
5. 记录未连接时网页能否打开与手机显示的出口；先结束其他 VPN。点击“连接”并确认路由、DNS 和可能替换其他 VPN 的影响。
6. 看系统真实状态，再点击“读取扩展统计”。在 Safari 发起请求后再次读取，检查双向计数变化；计数变化本身不证明出口正确。
7. 在手机本地比较连接前后的出口与预期节点是否一致，不把 IP、节点名或凭据贴到普通日志。确认域名请求成功，并按下面验收表检查 DNS 和所需协议。
8. 点击“断开”，等待未连接，确认网页恢复；再连接一次，重复测试。异常时先断开，必要时到“设置 → 通用 → VPN 与设备管理”关闭本应用 VPN。

## 测试 Ping（构建 12 起）

首页“网络测试 → 测试 Ping”打开独立页面。连接 VPN 后手动点击“测试 Ping”，显示测试中、毫秒数或明确失败状态及时间。构建 14 通过扩展中的 `HakoURLTestWithTimeout` 指定 MATCH 的实际节点，向 Cloudflare HTTP 204 发出 HEAD；统一延迟通常计复用连接后的第二次响应，第二次失败时内核可能回退到包含首次请求的总耗时。只有 2xx 响应计为成功，不是 ICMP RTT、HTTPS 握手或带宽测试，不自动切换节点。构建 12–13 使用 Google HTTPS 204 并计首次请求，历史结果不可直接比较。

未连接时按钮禁用。测试与“检查节点与 DNS”互斥，主 App 和扩展均阻止重复并发。返回首页不取消本次测试；断开、重新连接或进入等待网络恢复状态后清除旧结果并丢弃迟到回复。结果仅留在 App 内存中，IPC 只传固定枚举和有界毫秒数，不传节点名、凭据、响应内容或原始错误。

固定内核接口用 `-1` 合并网络错误、超时及非 2xx，因此 UI 显示“请求失败或超时”，不据此判断节点必然失效。构建 14 使用 10 秒内核 context，主 App 等待最多 10 秒并丢弃迟到回复；不再沿用旧版 5 秒内核/75 秒界面。等待超时不保证底层请求已结束，上游 QUIC 曾超过 context 时限；扩展仍在收尾时后续测试会返回忙碌，断开操作不等待测速完成。

## 已明确添加的网络行为

导入时保留约定的原始节点、组、规则与带宽参数，并明确确认以下新增默认值：

- `gvisor` 数据平面；路由由 `NEPacketTunnelNetworkSettings` 安装，MTU 为 1280。Swift 使用公开 `NEPacketTunnelFlow` 与 socketpair，Hako 持有副本 FD，Adapter 负责原始 FD；不读取私有 utun FD。
- IPv4 和 IPv6 默认路由、DNS AAAA 开启；系统保留流量与已有更具体路由仍可能不受默认路由覆盖，尚未做无泄漏保证。IPv6/UDP 必须实测。
- `redir-host` DNS，常规查询通过代理使用 Cloudflare DoH `https://1.1.1.1/dns-query`，`respect-rules: true`。构建 10 起，节点域名的引导解析直接使用安装隧道设置前捕获的系统 DNS，这部分并不在代理内；未获取到可用 DNS 时明确失败。该快照目前不随网络切换更新，切网需手动重连。普通域名 DoH 路径尚待抓包或可控服务验证。
- 保持证书校验；输入 `skip-cert-verify` 等超出当前范围的字段会被拒绝。不开启嗅探、系统 hosts、Geo 自动下载、局域网监听或按需连接；不提供 ICMP 转发。
- 关闭内核持久缓存，日志级别 silent。Go 的 40 MiB MemoryLimit 是垃圾回收提示，不能代表进程总量或 iOS 给扩展的上限；Swift 桥接排队上限 256 包／512 KiB，底层 socket 缓冲另计。

本原型拒绝额外顶层/节点/组字段、多节点、多组、providers、其他规则、额外 DNS/TUN 输入及 YAML 多文档，不会静默忽略。文件上限 16 KiB。运行配置序列化必须使用 `.withoutEscapingSlashes`，否则该固定内核的 YAML 解析器会拒绝 JSON 的 `\/` 转义。

`port` 接受 1–65535 的整数和带引号的十进制数字，例如 `port: 443`、`port: "443"`、`port: '443'`，保留原始类型传给内核。数字字符串不接受前导零、进制前缀、正负号或空格，避免与固定内核的自动进制解析产生歧义。原型早期只接受数值类型，曾误拒绝合法的字符串端口，现已补充该兼容分支；这项修复不要求用户改写原文件。

## 凭据和诊断

主 App 与扩展使用 `$(AppIdentifierPrefix)Kenote.Clash` 钥匙串访问组。保存使用 `AfterFirstUnlockThisDeviceOnly`、禁用 synchronizable；锁屏后扩展可读，重启手机后必须先解锁一次。没有 App Group 文件共享，也不把原始 YAML 保存到应用文件。

`Configuration/Patches/hako-private-diagnostics.patch` 添加 `PrivateDiagnostics`：关闭原始日志输出和最近日志收集、启动阶段文件、启动失败 breadcrumb 与 Go 独立崩溃日志。Swift 不显示原始 NSError、差异 given、配置 hash 或 node 内容。系统本身仍可能生成崩溃诊断，不能承诺整个操作系统不会留存任何诊断。

构建 3 的连接错误 2008 暴露了初始化选项的冲突：上游 `DisablePersistentCache` 同时启用“仅 App 预检”限制，`NewService` 因此被拒绝。隐私补丁现增加独立的 `EphemeralPacketTunnel` 选项，只允许 `iosPacketTunnel`、关闭持久缓存、启用隐私诊断且平台声明位于 NE 的组合创建服务；原来的 App 预检限制仍保留。此模式启用 NE 内存压力监控，数据库保持关闭。主 App 的调试检查用拒绝网络操作的替身平台验证创建与关闭，不能代替扩展中的实际启动验收。

构建 4/5 的启动错误 2012 经固定分类确认位于 `secure Clash API Unix socket`，系统原因是 `missing-file`；已经缩短路径仍失败，因此不能把原因直接断言为路径长度。构建 6 的本地补丁增加 `DisableClashAPISocket`，本客户端使用原生 Go 桥接与 NE 消息，不启动内部 Unix HTTP 管理接口。启用后真机启动成功。原配置契约仍拒绝 external-controller 等字段，工作目录保持受保护的临时目录。底层 Unix listener 为什么没创建成功尚未单独定位。

构建 6–9 使用固定直连 `1.1.1.1` 引导解析；构建 9 的分阶段诊断实测该步骤超时。构建 10 改为启动前读取系统 DNS，保持网站 DoH 路由不变；真机复测已成功打开 ping0.cc，用户确认出口符合预期。

“检查节点与 DNS”为手动诊断：节点域名引导解析、经节点请求 `https://1.1.1.1/cdn-cgi/trace`、内核解析 `ping0.cc`。结果只输出固定分类、延迟和计数，不返回原始错误、解析 IP、HTTP 响应或节点名。诊断不自动运行，不改变策略组；通过也不能替代 Safari、实际出口及泄漏验证。上游 QUIC 调用曾超过声明的 5 秒 context 才返回，客户端诊断等待上限暂为 75 秒，诊断与生命周期队列分开，断开无需等待探测结束。
