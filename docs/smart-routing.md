# 智能分流（2026-10-06）

入口：设置 → 连接 → 分流方案。按当前订阅选择、预览并保存；默认遵循订阅。

## 行为

- 原订阅所有明确规则保持顺序，最后的代理 MATCH 前插入 `GEOSITE,cn,DIRECT` 与 `GEOIP,CN,DIRECT`。因此明确代理／拦截规则仍然优先，不能承诺每项国内业务必定直连。
- 原文保持不变，选项记录在版本化依赖快照中；刷新沿用选项，关闭可恢复原订阅策略。已有版本历史、回滚、启动失败恢复流程复用。
- 未自定义 DNS 时，国内域名与直连出口用 AliDNS／DNSPod 的 HTTPS 解析器并显式 DIRECT，其他 DNS 用末尾代理目标；节点域名由连接前的系统 DNS 引导。已有 DNS 策略不覆盖，仅补充缺失的 direct-nameserver。
- 启用阶段仅使用校验过的本机依赖或内置 Geo 数据。缺失自定义资源、校验失败、规则超限、MATCH 为 DIRECT／REJECT 时拒绝候选版本，原版不变。
- 不依赖国内 IP 的系统 excludedRoutes；流量由内核按规则选择 DIRECT 或代理。UDP、IPv6 和既有节点选择策略继续沿用现有运行时。

## iOS 内存与编译缓存

真机曾在扩展内编译 cn 分类时触发约 50 MiB 的 per-process-limit。现在主 App 完整预检后把编译后的 MRS 分块保存到共享钥匙串；扩展按精确源快照、固定内核 ABI、文件长度与 SHA-256 校验后加载，避免在隧道进程重复编译。新智能分流版本缺少缓存时明确报错，沿用启动恢复流程。原始 Geo 资源仍保留供刷新、回滚和重新预检。

## 诊断

规则诊断 → 短时连接诊断：明确启动后由扩展每秒采样，60 秒停止，最多 30 条；5 分钟后、断开或切换节点清空。只保留内存数据，目标域名／IP 默认隐藏。不能识别所属 App，可能漏掉短连接／建立失败的连接，计数不证明消息送达。
